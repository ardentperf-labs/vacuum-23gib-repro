# 23 GiB Standard HDD: receiver disconnect and control

Two isolated East US stacks restore the same retained, verified, offline CNPG DATA/WAL snapshot pair. Each uses two Standard_D2s_v4 workers, PostgreSQL 16.15, CNPG 1.30.1, and separate 512 GiB Standard_LRS DATA and WAL disks on both primary and replica. Azure host caching is disabled. The original CNPG settings and preferred synchronous ANY 1 replica configuration are retained.

Both run VACUUM (VERBOSE, FREEZE) on the existing 23 GiB fixture and a tiny logged pgbench client: 5 TPS total, ten persistent connections, synchronous_commit=on, no latency limit or statement timeout. A five-minute healthy warm-up precedes VACUUM. Measurement continues for at least 140 minutes from VACUUM start, and longer if needed for VACUUM completion, replay catch-up and a healthy client tail.

The planned treatment sends one SIGTERM to the verified replica walreceiver at the actual remote SQL VACUUM start marker plus 600 seconds. The runner confirms one recovery-mode walreceiver in SQL, checks the matching Linux process PID, start time, UID, executable and command line, rechecks SQL and process identity, then sends `kill -TERM` to that PID. The control records the corresponding point without sending a signal. SIGTERM reproduces a receiver disconnect; the primary sender-timeout code path is a distinct trigger. Outcome claims follow the measurements.

Collectors retain primary/replica DATA/WAL reads/writes, linear-axis await/IOPS/throughput graphs, client native completion logs and latency, one-second session waits/ages/blockers, VACUUM progress, replication LSNs/senders/receiver, synchronous configuration, WAL/checkpoint counters, pg_stat_io and pg_stat_recovery_prefetch, Linux block/controller/queue/CPU/memory/pressure samples, and diagnostic BCC latency histograms. Azure captures exact disk and exact VM/per-LUN metrics at native one-minute grain, metric definitions, raw responses and missing-point evidence. CNPG operator logs and a Cluster watch record management changes.

The controller allows VACUUM to finish, downloads and checksums evidence, then deletes only verified owned snapshot-free test resources. The shared retained pair and its required local recovery metadata remain preserved. Snapshot access is serialized across the two stacks. No Git staging, commit or push is authorized.

Private runtime source metadata and kubeconfigs live outside the GitHub checkout. The published source preparation script requires locally supplied shared/source-pair.json, source-pair-proof.json, source-backup-status.json and source-restore-audit.json; these bind the exact private snapshot restore set and should not be copied from another subscription blindly. In the private experiment workspace, provision each stack, then run run-controller.py. Reviewed anonymized results are copied into the local GitHub checkout after measurement. Large raw text datasets may be gzip-compressed without changing their measurements; decompress them before using analysis helpers that expect the original filenames.

This folder is the late-signal pilot: the initial termination function returned false and the OS SIGTERM arrived at +673.729 seconds. Its restored clusters had no object-storage archive backend. See [DIAGNOSIS.md](DIAGNOSIS.md) for the write-resumption evidence and preparation mismatch. The planned mechanism above describes the corrected reusable helper; per-lane scripts and receipts retain the pilot behavior.
